# Telegram Bot для сбора данных и отправки в n8n

Telegram-бот для автоматизированного сбора данных (фото, диалог, описание сцены) с последующей отправкой в n8n webhook для обработки.

## Описание

Бот позволяет пользователям пройти интерактивный процесс сбора данных в три этапа:
1. Отправка фотографии
2. Отправка текста диалога
3. Отправка описания сцены

После сбора всех данных они автоматически отправляются в настроенный n8n webhook для дальнейшей обработки.

## Технологический стек

- Python 3.10+
- python-telegram-bot 21.10 - фреймворк для работы с Telegram Bot API
- aiohttp - асинхронный HTTP-клиент для отправки данных в webhook
- python-dotenv - управление переменными окружения
- asyncio - асинхронное выполнение операций

## Архитектура

Бот построен на основе `ConversationHandler` из библиотеки `python-telegram-bot`, что обеспечивает:
- Управление состояниями диалога (State Machine)
- Последовательный сбор данных от пользователя
- Возможность отмены операции на любом этапе
- Изолированное хранение данных для каждого пользователя

### Состояния диалога

```
START -> /generate -> PHOTO -> DIALOG -> SCENE_DESCRIPTION -> SEND_TO_WEBHOOK -> END
                        |         |              |
                        +-------- /cancel -------+
```

## Установка и настройка

### 1. Клонирование репозитория

```bash
cd /Users/volkovvladislav/PycharmProjects/nBot
```

### 2. Создание виртуального окружения

```bash
python3 -m venv .venv
source .venv/bin/activate  # На Windows: .venv\Scripts\activate
```

### 3. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 4. Настройка переменных окружения

Создайте файл `.env` на основе `.env.example`:

```bash
cp .env.example .env
```

Откройте `.env` и заполните необходимые значения:

```env
TELEGRAM_TOKEN=your_telegram_bot_token_here
N8N_WEBHOOK_URL=https://n8n.true-scale.ru/webhook/***REMOVED***
```

**Где получить TELEGRAM_TOKEN:**
1. Откройте Telegram и найдите [@BotFather](https://t.me/BotFather)
2. Отправьте команду `/newbot`
3. Следуйте инструкциям для создания бота
4. Скопируйте полученный токен в `.env`

### 5. Запуск бота

```bash
python bot.py
```

Или с использованием прав на выполнение:

```bash
chmod +x bot.py
./bot.py
```

## Использование

### Команды бота

- `/start` - Приветствие и показ главного меню
- `/generate` - Начать процесс сбора данных
- `/cancel` - Отменить текущую операцию
- `/help` - Показать справку

### Кнопки интерфейса

- **Начать генерацию** - Запускает процесс сбора данных (аналог `/generate`)
- **Помощь** - Показывает справочную информацию

### Процесс работы

1. Отправьте боту команду `/start` или `/generate`
2. Отправьте фотографию
3. Отправьте текст диалога
4. Отправьте описание сцены
5. Дождитесь подтверждения отправки данных

На любом этапе можно отменить операцию командой `/cancel`.

## API спецификация

### Формат данных, отправляемых в webhook

```json
{
  "user_id": 123456789,
  "username": "user_name",
  "photo_file_id": "AgACAgIAAxkBAAI...",
  "photo_base64": "iVBORw0KGgoAAAANSUhEUgAA...",
  "dialog": "Текст диалога от пользователя",
  "scene_description": "Описание сцены от пользователя"
}
```

### Поля payload

| Поле | Тип | Описание |
|------|-----|----------|
| `user_id` | integer | ID пользователя в Telegram |
| `username` | string | Username пользователя (может быть null) |
| `photo_file_id` | string | File ID фотографии в Telegram |
| `photo_base64` | string | Фотография в формате Base64 |
| `dialog` | string | Текст диалога |
| `scene_description` | string | Описание сцены |

## Обработка ошибок

Бот включает следующие механизмы обработки ошибок:

1. **Валидация конфигурации** - проверка наличия обязательных переменных окружения при запуске
2. **Обработка ошибок при скачивании фото** - повторный запрос при неудаче
3. **Timeout для webhook** - 30 секунд на отправку данных
4. **Логирование** - все события и ошибки записываются в лог
5. **Graceful shutdown** - корректная остановка бота по Ctrl+C

## Логирование

Бот ведет подробное логирование всех операций:

- Запуск/остановка бота
- Действия пользователей (команды, отправка данных)
- Успешные отправки в webhook
- Ошибки и исключения

Формат логов:

```
2025-12-08 15:30:45 - __main__ - INFO - Запуск бота...
2025-12-08 15:31:12 - __main__ - INFO - Пользователь 123456789 (username) запустил команду /start
2025-12-08 15:32:05 - __main__ - INFO - Данные пользователя 123456789 успешно отправлены в webhook
```

## Безопасность

### Реализованные меры

1. **Защита токенов** - токены и URL хранятся в `.env` (исключен из Git)
2. **Валидация входных данных** - проверка типов сообщений через фильтры
3. **Изоляция данных пользователей** - данные хранятся в `context.user_data`
4. **Timeout для внешних запросов** - предотвращение зависания
5. **Логирование без чувствительных данных** - не логируются токены и полные данные

### Рекомендации

- Не коммитьте файл `.env` в репозиторий
- Используйте сильные токены
- Регулярно обновляйте зависимости
- Мониторьте логи на предмет подозрительной активности
- Ограничьте доступ к серверу, где запущен бот

## Производительность

- **Асинхронная архитектура** - все операции выполняются асинхронно (async/await)
- **Эффективная работа с памятью** - фото конвертируется в base64 в памяти без записи на диск
- **Timeout контроль** - предотвращение зависания при проблемах с сетью
- **Легковесное хранилище** - данные пользователя очищаются после отправки

## Масштабирование

Для продакшн-окружения рекомендуется:

1. **Использовать базу данных** для хранения истории операций
2. **Добавить очередь сообщений** (Redis, RabbitMQ) для обработки запросов

## Troubleshooting

### Бот не запускается

- Проверьте, что установлены все зависимости: `pip install -r requirements.txt`
- Убедитесь, что файл `.env` существует и содержит корректные значения
- Проверьте, что токен бота валиден

### Бот не отвечает на сообщения

- Проверьте логи на наличие ошибок
- Убедитесь, что бот не заблокирован в Telegram
- Проверьте интернет-соединение

### Ошибка при отправке в webhook

- Проверьте доступность URL webhook
- Убедитесь, что URL корректен
- Проверьте логи n8n на стороне сервера
